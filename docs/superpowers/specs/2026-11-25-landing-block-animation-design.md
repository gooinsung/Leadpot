# 랜딩 블록 등장 애니메이션 — 설계 (짧은 설계)

- 작성: 2026-11-25
- 상태: 사용자 승인 대기

## 의도 · 왜

랜딩 편집기에서 **블록마다** 스크롤 등장 애니메이션을 골라 붙일 수 있게 한다. 코드를 모르는 고객도
클릭만으로 "스크롤할수록 요소가 하나씩 올라오는" 살아있는 랜딩을 만들게 하려는 것이다.

참고 영상(사용자 첨부, 자동차 장기렌트 랜딩 19초): 스크롤하면 제목·말풍선·브랜드 바·차량 카드 한 줄씩이
**흐릿한 상태에서 아래→위로 살짝 올라오며 선명해진다**(페이드업). 화면에 처음 들어올 때 한 번만 재생된다.
하단 고정 CTA 버튼은 움직이지 않는다. 반복(루프) 애니메이션은 없다.

## 목표

- 이미지·텍스트·HTML·리드폼(인라인)·외부 폼·CTA 버튼 블록에 각각 등장 애니메이션을 고를 수 있다.
- HTML 블록 **안쪽 요소**도 따로 등장시킬 수 있다(영상처럼 카드 한 줄씩).
- 공개 랜딩(SSR 렌더러)과 편집기 미리보기가 똑같이 움직인다.

## 비목표

- 반복(루프) 애니메이션(둥둥 떠다니기·반짝임), 속도·이징 커스터마이즈.
- 페이지 전체 기본값/일괄 적용(사용자가 블록별 방식 A 를 골랐다).
- 리드폼 편집기·독립 공개 폼(`/f/{id}`) 안의 항목 애니메이션.

## 반(反)목표 — 이러면 동작해도 실패

- 자바스크립트를 안 돌리는 크롤러·광고 심사 봇에게 콘텐츠가 **안 보이는** 것(숨긴 콘텐츠로 오해).
- 스크립트 오류 등으로 블록이 **영영 투명한 채** 남는 것.
- 위아래로 스크롤할 때마다 다시 재생되는 것(한 번만).
- 첫 화면이 깜빡이는 것(서버가 그린 콘텐츠가 보였다가 사라졌다 다시 나타남).

## 제약

- 공개 화면은 모바일 퍼스트(CLAUDE.md). 375px 에서 먼저 검증.
- 블록 데이터는 `content_json` 의 자유 키 — **백엔드·DB 변경 없이** 블록에 키만 추가한다.
- `packages/public-ui` 를 관리 앱과 렌더러가 공유한다. 렌더링 로직은 여기 한 곳에 둔다.

## 접근 방식(검토한 것)

| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 블록마다 따로 설정 (선택)** | 블록마다 효과·지연을 고른다 | 세밀하다. 블록이 많으면 여러 번 골라야 한다 |
| B. 페이지 전체 스위치 | 한 번 켜면 전 블록에 같은 효과 | 간단하지만 블록별 차이를 못 준다 |
| C. 페이지 기본값 + 블록별 덮어쓰기 | B + 예외만 블록에서 | 가장 유연하지만 설정 두 겹 |

사용자가 **A** 를 골랐다(2026-11-25).

## 설계

### 데이터(블록 키 추가)

- `anim`: `"fade-up" | "fade" | "zoom-in" | "slide-left" | "slide-right"` — 없으면 애니메이션 없음(기존 랜딩 영향 0).
  - `slide-left` = 왼쪽에서 들어옴, `slide-right` = 오른쪽에서 들어옴.
- `animDelay`: 지연(ms). 편집기 선택지 0 / 100 / 200 / 300 / 500. 없으면 0.
- 재생 시간은 0.7초 고정(내 판단 — 영상 체감과 비슷, 옵션을 늘리지 않으려고).

### 공개 렌더(`packages/public-ui`)

- 블록의 최상위 요소(img·p·HtmlBlock div·폼 카드·CTA 버튼)에 `data-lp-anim`, `data-lp-anim-delay` 속성을 단다.
  HTML 블록 안의 요소도 같은 속성을 쓰면 똑같이 동작한다(같은 문서에 주입되므로 — HtmlBlock.tsx 주석).
- 공통 CSS(`styles/` 에 새 파일): `.lp-anim-on [data-lp-anim]:not(.lp-in)` 만 숨긴다(효과별 시작 위치).
  `.lp-in` 이 붙으면 원위치로 전환.
- 훅 `useRevealAnimations(containerRef)`: 컨테이너 안의 `[data-lp-anim]` 을 IntersectionObserver 로 관찰,
  들어오면 `.lp-in` 을 붙이고 관찰 해제(한 번만). HTML 블록 스크립트가 나중에 만든 요소도 잡도록
  MutationObserver 로 새 노드를 추가 관찰한다.
- **크롤러·실패 안전장치**: 숨김은 `lp-anim-on` 클래스가 있을 때만 걸린다. 이 클래스는 SSR HTML 안의 아주 작은
  인라인 스크립트가 **첫 페인트 전에** 붙인다(깜빡임 방지). JS 가 없으면 클래스가 없어 전부 보인다.
  인라인 스크립트는 일정 시간(약 3초) 안에 훅이 시작됐다는 표시가 없으면 클래스를 떼서 전부 보이게 한다.
  IntersectionObserver 미지원 브라우저도 전부 보이게 한다.
- `prefers-reduced-motion: reduce` 이면 숨기지도 움직이지도 않는다.
- **적용 제외**: `floating`(화면 하단 고정) CTA, 오버레이·풀스크린 안의 폼.
- "구글 광고용"(`googleAdsSafe`) 랜딩: `sanitizeHtml` 은 `data-*` 속성을 지우지 않으므로 HTML 안쪽 애니메이션도
  유지된다. 인라인 제어 스크립트는 HTML 블록이 아니라 렌더러 자체 코드라 정화 대상이 아니다.

### 편집기(`frontend/src/pages/LandingEditPage.tsx`)

- 각 블록의 여백 설정 옆에 **"등장 애니메이션"** 선택(없음/아래에서 위로/서서히/확대/왼쪽에서/오른쪽에서)과
  **"지연"** 선택을 추가한다. `floating` 이 켜진 CTA 에서는 숨긴다.
- HTML 블록 입력칸 아래에 안내: `data-lp-anim="fade-up"` 을 붙이면 그 요소만 따로 등장한다.
- 미리보기(iframe)도 같은 훅·CSS 를 쓴다. 효과를 바꾸면 해당 블록이 다시 재생돼 바로 확인할 수 있다.

## 빌더에게 맡기는 것

- 효과별 시작 transform 의 정확한 값(예: fade-up 24~30px), 이징 곡선.
- 인라인 스크립트를 넣는 정확한 위치(LandingView 출력 안 vs 렌더러 레이아웃)와 미리보기 iframe 쪽 적용 방법.
- 훅의 테스트 범위(public-ui 의 vitest), 375px Playwright 확인.

## 검증

- 375px: 스크롤하며 블록이 한 번씩 올라오는지, 가로 스크롤 없는지.
- JS 끈 상태(또는 HTML 소스)에서 모든 콘텐츠가 보이는지.
- `anim` 없는 기존 랜딩이 전과 완전히 같은지.
- 편집기 미리보기에서 효과 변경 시 재생되는지.
