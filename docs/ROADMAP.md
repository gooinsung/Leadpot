## 프로젝트 = Leadpot (리드팟)

디비카트 벤치마킹 — 랜딩페이지로 리드(DB)를 수집·관리하는 서비스. 차별점: **폼 독립·재사용 + 폼 유형(기본형/스텝형) 확장 구조 + 폼 내 콘텐츠 블록**.

## 1차 확정 범위 (34개)

| 영역 | 선택된 기능 |

### Phase별 검증 기준
- **0**: 배포된 React 화면에서 `api.도메인/api/health` 호출 성공(CORS 포함)
- **1**: 가입→로그인→내 데이터만 보이는 대시보드 진입
- **2**: 기본형·스텝형 폼 생성→미리보기 동작
- **3**: 랜딩 생성→폼 연결→미리보기
- **4**: 공개 링크→폼 제출→리드+방문자정보(IP/OS/기기) 저장
- **5**: 리드 목록/상태/CSV/휴지통/중복·IP차단/통계 동작
- **6**: 픽셀 삽입·전환/클릭 데이터 확인
- **7**: 신규 리드 카카오 알림톡 발송
- **8**: 마케터가 광고주 초대→권한부여 → 광고주가 **부여된 폼의 리드만** 열람·상태변경·엑셀 / 미부여 폼 404 / 응답에 IP·UTM 부재 / 삭제 API 부재 / 양쪽 텔레그램 수신

## 작업 방식 (매 Phase 공통)

0. **착수 전 기획 재검증(필수)**: 관련 기획 문서 재정독 → 이 Phase 계획이 현실적·타당한지 재점검 → 의문/리스크 있으면 사용자와 조정 후 착수. (CLAUDE.md "각 Phase 착수 전 필수 절차" 참고)
1. 브랜치 생성 → 구현 → 로컬 검증(`docker-compose up` + `npm run dev`)
2. 원자적 커밋(한국어) + 관련 문서 갱신
3. 배포(push→CF Pages 자동빌드 / VM 컨테이너 재기동) → 스모크 테스트
4. Phase 검증 통과 시 다음으로. 이 문서의 상태표(⬜/🔄/✅) 갱신
