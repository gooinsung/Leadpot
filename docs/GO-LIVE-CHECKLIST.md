> **목적**: 실고객 리드가 쌓이기 시작하면 되돌리기 어려운 것들을 오픈 **전에** 잡는다.
> **사용법**: 지금부터 A(검증)를 하나씩 확인하고, 오픈 직전에 B(전환 작업)를 실행한다.
> 상태가 바뀌면 이 문서의 체크박스를 갱신하고 커밋한다. 진행상황 정본은 [PROGRESS.md](PROGRESS.md).

- **현재 상태**: 코드는 라이브(https://app.lead-pot.com), **실고객은 아직 없음** → 지금이 정리할 시기.
- **⚠️ 지금 가장 큰 위험**: 개발과 운영이 **같은 DB(Neon 1대)** 를 쓴다. 로컬에서 서버만 켜도 실데이터가 바뀐다.

## A. 지금부터 검증할 것 (시간을 두고)

### A-1. 데이터 · 백업 🔴 최우선

- [ ] **개발/운영 DB 분리** — Neon 브랜치로 개발용을 따로 판다. `application-local.properties` 는 개발 브랜치를 보게 한다.
  - 지금은 로컬 `bootRun` 만 해도 운영 데이터가 바뀐다. **실고객 리드가 들어오기 전에 반드시.**
  - 사용자 결정(2026-08-01): "DB 싹 갈아도 된다" → 새로 만들 때 나누면 된다.
- [ ] **Neon 백업·복구 확인** — 자동 백업 주기와 **복구를 실제로 한 번 해본다**(안 해보면 백업이 있는지 모르는 것과 같다).
- [ ] **테스트 데이터 정리** — 현재 Neon 에 스모크용 계정·리드가 섞여 있다(`*@test.local`, `테스트1~17`, `홍길동`, `김일덩` 등). 운영 전환 시 제거.
- [ ] **개인정보 보관 기준** 정하기 — 리드(이름·연락처)를 언제까지 보관하고 언제 파기할지. 휴지통 영구삭제 정책 포함.

### A-2. 보안 🔴

- [ ] **오리진 방화벽을 Cloudflare 대역으로 제한** — 오리진 IP(`129.225.198.2`)에 직접 붙으면 `CF-Connecting-IP` 가 없어 **위조 가능한 XFF 로 되돌아간다**. IP 차단·중복방지·통계가 다시 조작 가능해진다.
  - VM iptables 또는 Nginx 에서 [Cloudflare IP 대역](https://www.cloudflare.com/ips/)만 80/443 허용.
  - 배경: 2026-08-01 XFF 위조 취약점 수정(`8928b84`) 참고.
- [ ] **비밀번호 변경 시 기존 리프레시 토큰 무효화** — 지금은 비번을 바꿔도 기존 토큰이 최대 14일 살아 있다. `token_version` 필드 필요.
- [ ] **채팅·문서에 노출된 자격증명 정리** — 세션 중 공유된 비밀번호 변경, 발급했던 Cloudflare API 토큰 Revoke(현재 CI 는 SSH 키를 쓰므로 불필요).
- [ ] **HTML 블록 신뢰 경계 재확인** — 마케터가 넣은 임의 JS 가 공개 페이지에서 실행된다(의도된 설계). 광고주 계정에는 편집 권한이 없음을 재확인.
- [ ] **Cloudflare "Always Use HTTPS"** 토글 확인.

### A-3. 기능 실동작 (실데이터로)

- [ ] **핵심 루프 E2E** — 가입 → 리드폼 생성 → 랜딩 공개 → **실제 서브도메인 랜딩 열기** → 제출 → 리드 수신 → 상태변경.
- [ ] **광고주 포털 실화면** — 광고주 계정으로 로그인해 할 일 큐·모바일 확인. (2026-08-01 U6 는 자격증명이 없어 **포털 내부를 못 봤다** — CSS 프로브까지만 검증)
- [ ] **알림 실수신** — 텔레그램 봇 토큰·채팅ID 를 넣고 실제로 받아본다. 구글시트 웹훅도.
- [ ] **전역 접속 차단** — 실제 IP 로 랜딩이 404 가 되는지. ⚠️ **본인 IP 를 넣으면 본인도 못 본다**(관리 화면은 영향 없으니 거기서 해제).
- [ ] **모바일 실기기** — 공개 폼·랜딩을 실제 폰에서. (지금까지는 브라우저 시뮬레이션·DOM 실측만)
- [ ] **결제 전 플랜 상한** 동작 — 리드폼·광고주 수 제한이 의도대로 걸리는지.

### A-4. 운영 준비

- [ ] **도메인 apex(`lead-pot.com`) A레코드** — 현재 미설정. 필요하면 추가.
- [ ] **에러 모니터링** — 지금은 서버 로그를 직접 봐야 한다. 최소한 백엔드 예외 알림이라도.
- [ ] **미사용 리소스 정리** — Cloudflare Pages 프로젝트 `leadpot`(미사용), 서버 `.env` CORS 의 `leadpot.pages.dev`.
- [ ] **약관·개인정보처리방침** 실제 내용으로 교체(현재 샘플).

## B. 오픈 직전에 실행할 것

- [ ] **DB 전환** — 운영 DB 를 새로 만들고(또는 정리하고) `.env` 의 `SPRING_DATASOURCE_*` 교체 → 재배포 → Flyway 적용 확인.
- [ ] **테스트 계정·데이터 삭제**.
- [ ] **JWT 시크릿 재발급**(`APP_JWT_SECRET`) — 개발 중 쓰던 값과 분리. 교체하면 기존 세션은 전부 로그아웃된다.
- [ ] **오리진 방화벽 적용**(A-2 첫 항목) — 적용 후 실제 접속이 되는지 즉시 확인.
- [ ] **배포 후 스모크** — 헬스 → 로그인 → 공개 랜딩 열기 → 제출 1건 → 리드 확인.
- [ ] **롤백 경로 확인** — 문제 시 직전 커밋으로 `git revert` 후 재배포하면 되는지, DB 마이그레이션은 되돌릴 수 있는지 미리 정리.

## 참고 — 배포·인프라 현황

- 프론트 `app.lead-pot.com` / 백엔드 `api.lead-pot.com`, 둘 다 **같은 Oracle VM 의 Nginx**가 서빙(Cloudflare Pages 는 와일드카드 미지원이라 접었다).
- `main` push → GitHub Actions 자동배포. 프론트는 rsync(무중단), 백엔드는 재빌드(2~4분, 그 사이 API 순단).
  - ⚠️ 백엔드 재배포 중 로그아웃되던 문제는 수정됨(`749e73c`).
- DB = Neon(ap-southeast-1). **Flyway 현재 V21 까지 → 다음은 V22.**
- 상세(서버 세팅·SSH 키·Cloudflare 설정·재배포 명령)는 [PROGRESS.md](PROGRESS.md) 배포 섹션 참고.
