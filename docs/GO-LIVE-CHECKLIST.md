# docs/GO-LIVE-CHECKLIST.md — 실서비스 오픈 전 점검표

> **목적**: 실고객 리드가 쌓이기 시작하면 되돌리기 어려운 것들을 오픈 **전에** 잡는다.
> **사용법**: 지금부터 A(검증)를 하나씩 확인하고, 오픈 직전에 B(전환 작업)를 실행한다.
> 상태가 바뀌면 이 문서의 체크박스를 갱신하고 커밋한다. 진행상황 정본은 [PROGRESS.md](PROGRESS.md).

- **현재 상태(2026-09-15)**: 코드는 라이브(https://app.lead-pot.com), **실고객이 이미 광고를 집행 중이고
  실제 리드가 쌓이고 있다.** 아래 미완 항목은 "오픈 전"이 아니라 **지금 밀린 숙제**다.
- ⚠️ 이 문서는 2026-08-01 기준으로 작성돼 **Neon·Oracle VM 전제**가 남아 있었다. 2026-09-15 에
  현재 구성(Railway + Cloudflare)으로 갱신했다. 인프라 현황은 [ARCHITECTURE.md](ARCHITECTURE.md) §1 이 정본.

## A. 지금부터 검증할 것 (시간을 두고)

### A-1. 데이터 · 백업 🔴 최우선

- [x] **개발/운영 DB 분리** — ✅ 해결됨(2026-08-18). 로컬은 `docker compose` 의 `postgres:18` 을 보고,
  프로덕션은 **Railway Postgres 내부망 전용**이라 외부에서 접근 자체가 불가능하다.
  (예전엔 모든 환경이 Neon 한 대를 공유해 개발 PC마다 프로덕션 DB 비밀번호가 있었다.)
- [ ] **Railway Postgres 백업·복구 확인** — 자동 백업 주기와 **복구를 실제로 한 번 해본다**(안 해보면 백업이 있는지 모르는 것과 같다).
- [ ] **테스트 데이터 정리** — 스모크용 계정·리드가 섞여 있다(`*@test.local`, `테스트1~17`, `홍길동`, `김일덩` 등). ⚠️ 실고객 데이터가 이미 같은 DB에 있으므로 **지울 대상을 정확히 골라내고 백업 후** 진행할 것.
- [ ] **개인정보 보관 기준** 정하기 — 리드(이름·연락처)를 언제까지 보관하고 언제 파기할지. 휴지통 영구삭제 정책 포함.

### A-2. 보안 🔴

- [ ] 🔴 **오리진 직접 접근 차단** — 백엔드가 Railway 로 옮겨가면서 대상이 바뀌었다. 지금 막아야 하는 건
  **Railway 가 주는 공개 주소(`*.up.railway.app`)로 직접 붙는 경로**다. Cloudflare 를 우회하면
  `CF-Connecting-IP` 가 없어 **위조 가능한 XFF 로 되돌아가고**, IP 차단·중복방지·통계가 다시 조작 가능해진다.
  - 대응 후보: Railway 쪽에서 공개 도메인을 없애고 커스텀 도메인만 두기 / 앱에서 Cloudflare 경유가
    아닌 요청 거부(`CF-Connecting-IP` 부재 시) 중 택1 — **사용자와 상의 후 결정**.
  - 배경: 2026-08-01 XFF 위조 취약점 수정(`8928b84`) · `backend/.../common/ClientIp.java` 참고.
- [ ] **비밀번호 변경 시 기존 리프레시 토큰 무효화** — 지금은 비번을 바꿔도 기존 토큰이 최대 14일 살아 있다. `token_version` 필드 필요.
- [ ] **채팅·문서에 노출된 자격증명 정리** — 세션 중 공유된 비밀번호 변경, 발급했던 Cloudflare API 토큰 Revoke(현재 CI 는 SSH 키를 쓰므로 불필요).
- [ ] **HTML 블록 신뢰 경계 재확인** — 마케터가 넣은 임의 JS 가 공개 페이지에서 실행된다(의도된 설계). 광고주 계정에는 편집 권한이 없음을 재확인.
- [ ] **Cloudflare "Always Use HTTPS"** 토글 확인.

### A-3. 기능 실동작 (실데이터로)

- [ ] **핵심 루프 E2E** — 계정 생성 → 리드폼 생성 → 랜딩 공개 → **실제 공개 랜딩(`go.lead-pot.com/{sub}/{id}`) 열기** → 제출 → 리드 수신 → 상태변경.
- [ ] **SSR 전환 후 회귀 확인** — 스텝폼·계산기·동의문서 인라인 펼침·오버레이/풀스크린 CTA·픽셀 발사·
  **IP 차단 실동작**·방문/스크롤/이탈 통계 ([SSR-LANDING-PLAN.md](SSR-LANDING-PLAN.md) §9-B).
- [ ] **광고주 포털 실화면** — 광고주 계정으로 로그인해 할 일 큐·모바일 확인. (2026-08-01 U6 는 자격증명이 없어 **포털 내부를 못 봤다** — CSS 프로브까지만 검증)
- [ ] **알림 실수신** — 텔레그램 봇 토큰·채팅ID 를 넣고 실제로 받아본다. 구글시트 웹훅도.
- [ ] **전역 접속 차단** — 실제 IP 로 랜딩이 404 가 되는지. ⚠️ **본인 IP 를 넣으면 본인도 못 본다**(관리 화면은 영향 없으니 거기서 해제).
- [ ] **모바일 실기기** — 공개 폼·랜딩을 실제 폰에서. (지금까지는 브라우저 시뮬레이션·DOM 실측만)
- [ ] **결제 전 플랜 상한** 동작 — 리드폼·광고주 수 제한이 의도대로 걸리는지.

## B. 아직 실행하지 않은 전환 작업

> ⚠️ 원래 "오픈 직전" 목록이었으나 이미 실서비스가 돌고 있다. 지금은 **실데이터가 있는 상태에서**
> 해야 하므로 각 항목마다 백업·롤백 경로를 먼저 확인하고 사용자와 시점을 합의한다.

- [x] **DB 전환** — ✅ Neon → Railway Postgres 완료(2026-08-18, 업무 데이터 유실 0건).
- [ ] **테스트 계정·데이터 삭제** (A-1 참고 — 실고객 데이터와 섞여 있다).
- [ ] **JWT 시크릿 재발급**(`APP_JWT_SECRET`) — 교체하면 **기존 세션이 전부 로그아웃된다**. 공지 후 진행.
- [ ] **오리진 직접 접근 차단**(A-2) — 적용 후 실제 접속이 되는지 즉시 확인.
- [ ] **배포 후 스모크** — 헬스 → 로그인 → 공개 랜딩 열기 → 제출 1건 → 리드 확인.
- [ ] **롤백 경로 확인** — 문제 시 `git revert` 후 재배포로 되는지. ⚠️ **Flyway 마이그레이션 파일은
  되돌리면 안 된다**(앱이 아예 안 뜬다) — 코드만 되돌린다.

## 참고 — 배포·인프라 현황 (2026-09-15)

- 관리 앱 `app.lead-pot.com` = **Cloudflare Pages**(`leadpot-app`) /
  공개 랜딩 `go.lead-pot.com/{sub}/{id}` = **Cloudflare Workers**(`leadpot-renderer`, SSR) /
  백엔드 `api.lead-pot.com` = **Railway**(싱가포르) / DB = **Railway Postgres**(내부망 전용).
- Oracle VM 은 **아직 켜져 있으나 실트래픽을 받지 않는다**(롤백 안전망, 종료 예정).
- `main` push → 경로별 GitHub Actions 자동배포. 백엔드는 Railway 자체 연동(무중단 롤링).
- **Flyway 현재 V43 까지 → 다음은 V44.**
- 전체 구성·함정은 [ARCHITECTURE.md](ARCHITECTURE.md) 가 정본. 경위는 [PROGRESS.md](PROGRESS.md).
