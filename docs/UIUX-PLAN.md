# docs/UIUX-PLAN.md — UI/UX 개선 로드맵

> 마케터·광고주 플랫폼의 UI/UX를 **사용자 편의성 중심**으로 마이그레이션하는 작업의 정본 계획.
> 최우선 가치: **① 가독성 ② 기능 편의성** (사용자 확정). 프레임은 넓게 사용.
> 착수 전 [../CLAUDE.md](../CLAUDE.md) §0 · [PROGRESS.md](PROGRESS.md) 확인. 상태가 바뀌면 이 문서를 갱신한다.

## 확정된 방향 (2026-07-31, 사용자)

- **마케터 플랫폼 먼저** → 이후 광고주.
- 리드: **폼별 뷰 유지 + 통합 인박스 페이지 추가**(①Inbox 모델).
- **홈 = 범용 대시보드 유지**.
- 상세 = **사이드 패널**(모달 아님) / 첫 화면 = **미확인 우선** / 연락처 = 목록 마스킹·상세 전체.

- 참고 산출물: 디자인 컨셉 4선(Cockpit/Daylight/Signal/Paper), 인박스 와이어프레임.

## U1 통합 인박스 — 실행 메모

- **백엔드**: `GET /api/leads/inbox?status=&q=&formId=&from=&to=&unseen=&page=&size=` — 내 모든 폼의 활성 리드 합산, 각 리드에 **출처 폼명(formName)** 포함. 사이드 카운트(미확인/오늘/전체 + 폼별·상태별).
  - "미확인" = 마케터 상태 **`NEW`(신규)** — 별도 컬럼/마이그레이션 없음.
  - 기존 `LeadResponse` 재사용하되 formName 추가(또는 인박스 전용 응답).
- **프론트**: 신규 페이지(3-pane, 넓은 프레임) — 왼쪽 필터 rail / 가운데 목록(출처 뱃지·상태 pill·미확인 강조) / 오른쪽 사이드 패널(기존 `LeadDetailModal` 로직 재사용, 읽기+상태변경+메모). 상단바에 '리드(통합)' 진입점 추가.
- **폼별 뷰**(`/forms/:id/leads`)는 유지 — 인박스는 새 진입점으로 **추가**.

## U2 사이드 패널 · 일괄작업 — 실행 메모

- **공용 컴포넌트 `components/LeadSidePanel.tsx`** 로 통일(인박스의 로컬 패널을 추출·확장). 두 가지 변형:
  - `variant="pane"` — 통합 인박스 3-pane의 오른쪽 칸(레이아웃 흐름 안).
  - `variant="drawer"` — 폼별 리드 목록에서 **우측에 겹치는 서랍**. **딤 배경 없음** → 뒤 목록이 계속 보이고 다른 리드의 '상세'를 바로 눌러 전환 가능(= 맥락 유지).
- 내용은 두 화면 합집합: 답변 · 상태 칩 · **태그 편집** · 방문자(IP·언어·유입·UTM) · 메모/이력(메모 삭제 가능). ESC 로 닫힘.
- `LeadDetailModal.tsx` 는 **삭제**(사용처 없음, 패널로 대체).
- **일괄작업은 인박스에만** 둔다(결정): 폼별 뷰는 카드 레이아웃이라 체크박스 열이 어색하고, 여러 폼을 한 번에 다루는 일괄작업의 성격상 인박스가 제자리. 폼별 뷰의 표/행 정리는 U3에서 다루고, 그때 필요하면 추가.

## U3 가독성 패스 — 실행 메모

**사용자 결정(2026-07-31)**: 폼별 리드 목록은 **컴팩트 행 목록으로 통일**(답변 인라인 카드 폐기, 전체 답변은 상세 패널).

- **폼별 리드 목록 = 한 리드 한 줄**(`.flead-*`): 이름(+중복·👁광고주확인 플래그) · 연락처(마스킹) · **나머지 답변 1줄 요약**(`lib/leadDisplay.ts` `summarizeAnswers`) · 상태 · 접수일시 · 액션. 줄 클릭 → 상세 서랍. 페이지당 10건 → **25건**.
  - 헤더 줄(`.flead-head`)과 데이터 줄이 **같은 열 폭 변수**(`--fl-act`)를 공유 — 휴지통은 액션 2개라 그 열만 넓힘.
  - 좁은 화면(≤900px)은 2열 4행으로 접힘(관리자 화면은 데스크톱 우선이지만 깨지지 않게).
- **표시 로직 공용화**: `frontend/src/lib/leadDisplay.ts`(이름·연락처 추출, 마스킹, 요약, 상태 라벨) — 인박스와 폼별 목록이 같은 규칙.
- **대비 개선(접근성)**: `*-soft` 배경 위 글자용 **ink 토큰** 신설(`--amber-ink`·`--rose-ink`·`--green-ink`·`--indigo-ink`·`--violet-ink`). 기존엔 앰버/로즈 원색을 연한 배경에 얹어 **대비 약 2~3:1** 이었음 → 전 상태 배지·pill·칩이 **5.0~8.4:1** (측정값, 라이트). 다크는 밝은 값으로 자동 전환.
- **상태색 단일화**: 마케터 상태색이 `.badge b-*` / `.ld-*` 두 벌로 갈려 있던 것을 **`.ld-*` 한 벌**로. `.ld-*`/`.st-*` 가 `--ld-*`/`--st-*` 변수를 내보내고 `.lead-status-select` 가 그 변수를 참조 → 상태별 중복 규칙 제거. **곁가지 수정**: 이 구조 덕에 광고주 화면의 상태 셀렉트가 회색으로만 보이던 문제(레이어 순서상 `.st-*` 가 밀림)도 해결.
- **표 정돈**: `th` 톤 배경 + 12px, 행 `padding` 13px·`vertical-align: middle`, 표 감싸는 카드에 **`card-table`**(모서리 클리핑) 적용 — 리드폼·랜딩·동의문서·요소·IP차단·광고주 목록.
- **타이포 토큰**: `--fs-xs|sm|md|lg|xl` 신설, 이번에 손댄 레이어부터 적용(나머지는 U7에서 이어서).
- **검증**: `tsc -b` + prod 빌드 통과 / 빌드된 CSS 로 정적 프리뷰를 띄워 **DOM 실측**(1440px·375px): 열 정렬 일치, 행 높이 61px 균일, 가로 스크롤 없음, 상태색 대비 전부 ≥4.5:1. ⚠️ 실앱 로그인 화면 확인은 사용자 몫.

## U1~U3 실앱 검증 결과 (2026-08-01)

**U0~U3 는 실앱(로그인 상태)에서 검증 완료.** 상세 기록 = [PROGRESS.md](PROGRESS.md).

- **통과**: 인박스 rail 카운트 DB 일치 · 3-pane 겹침 없음 · **폼별 목록 헤더-데이터 열 폭 완전 일치·행 높이 60px 균일** · 상태 셀렉트 색 정상 · 6개 목록 화면 표 회귀 없음 · 단건/일괄 상태변경·태그·메모·휴지통·복원 전부 정상(SYSTEM 이력은 삭제 불가가 맞게 동작).
- **✅ 확정: 답변 1줄 요약은 그대로 간다** — 실데이터에서 `2000만원~ 4000만원 · 집(자가)` 처럼 충분히 읽힌다. "목록에 보일 항목"을 리드폼 설정에 추가하는 안건은 **접는다**.
- **🐞 수정한 버그 2건**: ① `maskPhone` 이 11자리 번호를 `0101-234-··` 로 잘못 쪼갬 → 국번 기준으로 재작성(`010-1234-··`). ② 375px 에서 문서 폭이 뷰포트를 넘어(734px) `position:fixed` 서랍이 화면 밖으로 밀림 → 상단바·액션 바·날짜 범위 필터 세 곳의 줄바꿈/축소를 허용해 375px 로 정상화.
- **⚠️ U4 로 넘기는 것**: 위 ②는 넘침만 막은 임시 조치다. 375px 에서 **내비 가시 폭이 52px 뿐**이라 가로 스크롤로 훑어야 한다 — 상단바 그룹핑(또는 사이드바 전환)이 U4 의 실제 과제. `/advertisers` 행 액션이 **8개**(권한·정보·활동이력·리포트·미리보기·비번재설정·정지·삭제) 나열되는 것도 U4 에서 함께 정리.

## U4 내비게이션 — 실행 메모 (2026-08-01)

**결정 경위**: 처음엔 "상단바 유지 + 그룹핑"으로 정해 상단 드롭다운(제작 ▾ / 설정 ▾)을 만들어 배포했으나, 실제로 보고 **LNB(좌측 사이드바)로 전환**하기로 바꿨다(사용자). 드롭다운은 열어봐야 안이 보이는 반면 LNB 는 전부 펼쳐놓고 섹션 제목으로 위계를 준다.

- **구성**: (대시보드·리드) / **제작**(리드폼·랜딩·요소·동의 문서) / **운영**(광고주·통계·연동). 하위 항목엔 한 줄 설명, **존댓말 통일**(만듭니다·관리합니다·연결합니다).
- 계정(이메일·테마·로그아웃)은 사이드바 하단 메뉴 하나로.
- 좁은 화면(≤900px)은 **상단 바 + 드로어**. 로그인 등 내비 없는 화면엔 사이드바를 두지 않는다(`data-has-nav`).
- `.app-shell` 은 LNB 가 있을 때만 가로 배치(`:has`). 페이지는 손대지 않았다 — `TopBar` 컴포넌트만 바꿨다.
- **인박스가 4단이 되는 문제**(예고했던 것)가 실제로 발생: LNB 224 + rail 236 + 행 최소폭 524 + 패널 400 = **1384px** 이 필요해 1265px 화면에서 **119px 넘쳤다**. → 1400px 미만에서 rail 184 · 패널 344 로 줄이고 행 최소 열 폭도 낮춰 해소.
- **섹션 접기/펼치기**(사용자 요청): 섹션 제목이 토글. **현재 페이지가 든 섹션은 강제로 열림**, 펼침 상태는 `localStorage`(`lp.lnb.sections`)에 기억. 제목 없는 섹션(대시보드·리드)은 항상 노출.
- ✅ **행 액션 더보기**(`65c0d86`): `/advertisers` 한 행의 버튼 8개 → **`리드폼 권한` · `리포트` · `⋯`**. 나머지(정보 수정·활동 이력·광고주 화면 미리보기·비밀번호 재설정 링크)는 메뉴로, **되돌리기 어려운 계정 정지·삭제는 구분선 아래 빨간색**으로 분리. 버튼이 좁아 줄여 썼던 라벨은 메뉴에서 풀어썼다.
  - 공용 **[`components/RowMenu.tsx`](../frontend/src/components/RowMenu.tsx)** — 다른 목록에도 그대로 쓸 수 있다.
  - ⚠️ **표를 감싼 `.card-table` 이 `overflow: hidden`** 이라 행 안에서 드롭다운을 그리면 잘린다 → **`document.body` 포털 + `position: fixed`** 로 띄우고 버튼 좌표에 맞춘다. 화면 아래로 넘치면 버튼 위로 뒤집고, 바깥 클릭·ESC·스크롤·리사이즈에 닫힌다.
  - 검증(실앱): 메뉴 부모 `BODY` · 6항목 · 위험 2개 분리 · 뷰포트 안에 완전히 들어옴 · `elementFromPoint` 로 **잘리지 않고 실제로 보이는지** 확인 · ESC 닫힘 · 항목 클릭 시 메뉴 닫히고 모달 열림 · 가로 넘침 0.
- **다른 목록에도 적용**은 아직 — 필요할 때 `RowMenu` 를 끼우면 된다.

## U5 공통 상태 UX — 실행 메모 (2026-08-01)

**착수 전 조사에서 진단을 한 번 정정했다**: 처음엔 "빈 화면에 다음 행동 버튼이 없다"고 봤는데, 코드를 열어보니 목록 화면들은 **이미** 공통 클래스(`card card-pad empty-state`)에 상황별 문구와 행동 버튼을 갖추고 있었다. grep 결과만 보고 성급히 판단한 것. 실제 구멍은 성공 피드백·인박스 빈 화면·로딩 세 가지였다.

- ✅ **토스트**(`9135333`) — **성공 피드백이 아예 없던 것**이 가장 큰 구멍이었다(실패만 `auth-error` 로 표시). [`lib/toast.ts`](../frontend/src/lib/toast.ts) + [`components/Toaster.tsx`](../frontend/src/components/Toaster.tsx).
  - **컨텍스트가 아니라 모듈 수준 저장소** — 편집 화면 4곳이 저장 후 목록으로 이동하므로 **라우트가 바뀌어도 살아남아야** 한다. 실앱에서 `/new` 저장 → 목록에서 표시되는 것을 확인.
  - 실패는 `role="alert"` + 6초(성공 3초). 브라우저 기본 `alert()` 3곳(내보내기·가져오기)도 교체.
- ✅ **인박스 빈 화면**(`5014214`) — 한 줄 안내뿐이라 **리드가 없는 건지 필터에 걸린 건지 구분되지 않았다**. 전체 0건이면 리드폼으로 가는 버튼, 필터 결과 0건이면 **필터 초기화** 버튼.
- ✅ **삭제 피드백·에러 처리**(`5014214`) — 삭제는 성공해도 무반응이고 **실패해도 조용히 넘어갔다(에러 처리 자체가 없음)**. 리드폼·랜딩·동의문서·요소에 try/catch + 토스트.

## U7 비주얼 컨셉 — Cockpit (2026-08-01)

**사용자 확정**: 컨셉 **Cockpit** · **마케터 화면 먼저** · LNB 유지 · **색은 유지** · 톤의 무게는 **밀도·성과**.
컨셉 원문 = [artifact/a2a7625e](https://claude.ai/code/artifact/a2a7625e-c32f-42f7-91b0-93c068a4366b). Cockpit 팔레트(Ink #1B1E3A · Indigo #3A43C0 · Green #12B886)가 현재 토큰과 거의 같아 **색 유지 결정과 충돌이 없었다.**

- ✅ **잉크 사이드바**(`5ae4a93`) — Cockpit 의 가장 큰 인상 차이. 새 색을 들이지 않고 기존 잉크 팔레트로 `--lnb-*` 토큰 신설(라이트/다크 별도. 다크는 본문이 이미 어두우므로 한 단계 더 가라앉힘).
  - 🐞 잉크 배경으로 바꾸니 **섹션 제목(11px 볼드) 대비가 4.03:1** 로 기준 미달 → `--lnb-group` 을 올려 라이트 5.81 · 다크 6.41 (`43f1794`). **밝은 배경에서 괜찮던 색이 어두운 패널에서 깨지는 사례** — 패널 색을 바꿀 땐 그 위 글자 대비를 반드시 다시 잰다.
- ✅ **행 밀도 + 토글**(`5ae4a93`) — `--row-py/px/gap` 토큰으로 **표와 행 목록이 같은 리듬**으로 반응. 기본 촘촘(9px), 계정 메뉴에서 넉넉(13px), localStorage 기억([`lib/useDensity.ts`](../frontend/src/lib/useDensity.ts)).
