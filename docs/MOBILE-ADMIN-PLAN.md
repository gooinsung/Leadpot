# MOBILE-ADMIN-PLAN.md — 마케터·광고주 화면 모바일 최적화 계획

> 2026-10-29 작성(원격 세션, 사용자 지시). 진행 상황은 [PROGRESS.md](PROGRESS.md) 에 기록한다.

## 1. 범위 (사용자 확정)

| 대상 | 범위 |
|---|---|
| ✅ 마케터 사이트 `app.leadpot.kr` | 대시보드·리드 인박스·리드폼/랜딩 목록·통계·광고주·견적·문자·연동·내 정보 등 |
| ✅ 광고주 사이트 `/client/*` | 리드·리포트·설정(연동)·사용 안내·로그인 |
| ❌ 공개 랜딩 `{sub}.leadpot.kr/{id}`, 공개 리드폼 `/f/{id}`, 동의서 보기, `renderer/` | **건드리지 않는다**(사용자: "랜딩 쪽은 너무 좋다") |

- **휴대폰 사용 목적**: 대부분 **확인**, 가끔 **간단 수정** → 목록·대시보드·리드 처리 화면이 1순위,
  편집기는 "깨지지 않고 간단 수정이 되는" 수준까지만(전면 재설계 안 함).

## 2. 절대 원칙 — "모바일만 바뀐다"

1. 새 CSS 는 전부 **`@media (max-width: 900px)` 이하 구간 안**에만 넣는다. PC 폭에서는 적용되지 않는다.
2. 새 CSS 는 **`frontend/src/styles/` 에만** 둔다. `packages/public-ui/src/styles/` 는 공개 랜딩·렌더러도
   쓰므로 **수정하지 않는다**(수정하면 렌더러 재배포가 돌고 랜딩에 영향이 갈 수 있다).
   공용 클래스(`.kpis`·`.card-table`·`.folders-layout` 등)를 모바일에서 바꿔야 하면, 관리 앱 쪽 파일에서
   `.app-shell` / 광고주 셸 하위로 범위를 좁혀 덮어쓴다.
3. TSX 를 고쳐야 하는 경우(예: 표 → 모바일 카드)는 **PC 마크업은 그대로 두고** 모바일 전용 마크업을 추가해
   CSS 로 폭에 따라 하나만 보이게 한다.
4. 매 단계 **375px 캡처(변경 확인) + 1440px 캡처(PC 전후 동일 확인)** 를 함께 남긴다.

## 3. 사용자 캡처로 확인된 문제와 원인

| 증상 (아이폰, 2026-10-29) | 원인(코드) |
|---|---|
| 대시보드: KPI 카드가 화면 오른쪽 밖으로 잘림, 상단 바가 화면 폭보다 좁음 | 어떤 자식이 화면보다 넓어져 **페이지 전체가 가로로 넘친다**(문서 폭 > 375px) |
| 리드폼 목록: 페이지 전체가 축소돼 보임(상단 바가 화면의 절반) | `.folders-layout` 이 좁은 화면에서 `grid-template-columns: 1fr` — `1fr` 은 최소폭이 내용물 폭이라 **표가 그리드 칸을 밀어 페이지가 넓어지고**, iOS 가 넓어진 페이지를 축소해 보여준다. `minmax(0, 1fr)` 이어야 표가 카드 안에서만 스크롤된다 |
| 리드폼 목록: 폴더 트리가 위에 다 펼쳐져 아래 리드폼이 안 보임 | 900px 이하에서 폴더 트리가 1열로 쌓이며 **전부 펼친 채** 위에 붙는다 |
| 리드폼 목록: 표가 7열 + 버튼 3개라 모바일에서 읽기 어려움 | 모바일용 목록(카드형) 없음 |

→ **1순위는 "가로 넘침 0"**. 이게 잡혀야 나머지 레이아웃이 의미가 있다.

## 4. 단계

### Phase 0. 현황 캡처 (자동)
- 로컬 Vite + Playwright(API 는 가짜 응답)로 마케터·광고주 주요 화면을 **375px / 1440px** 캡처.
- 화면마다 `document.scrollingElement.scrollWidth > 375` 여부(가로 넘침)를 자동 측정해 표로 정리.
- 이 스크립트를 이후 단계의 회귀 확인용으로 계속 쓴다.

### Phase 1. 공통 기반
- **가로 넘침 제거**: 그리드/플렉스 자식 `min-width: 0`(`minmax(0,1fr)`), 표는 항상 가로 스크롤 카드 안.
- **하단 탭바(모바일 전용)** — 확인 위주 사용이라 자주 가는 곳을 엄지 거리에 둔다:
  - 마케터: `대시보드 · 리드 · 리드폼 · 랜딩 · 더보기`(더보기 = 나머지 메뉴 + 계정 메뉴를 바텀시트로)
  - 광고주: `리드 · 리포트 · 설정 · 안내`(메뉴 4개라 더보기 없음)
  - 상단 바는 로고 + 계정만 남기고 햄버거 드로어는 제거(PC LNB 는 그대로).
  - safe-area(`env(safe-area-inset-bottom)`) 대응, 본문 하단 여백 확보.
- 모바일 공통 규칙: 입력창 16px(iOS 확대 방지), 탭 타깃 44px 이상, 모달은 바텀시트형, 페이지 좌우 여백 16px.
- 반응형 기준폭을 관리 앱 쪽은 **≤900px(모바일·태블릿)** 와 **≤640px(휴대폰)** 둘로 통일.

### Phase 2. 자주 보는 화면 (확인 위주)
- **대시보드**: KPI 2열(숫자 크기 축소·`원` 같은 줄), 오늘 들어온 리드 목록, 서브도메인 카드 정리.
- **리드 인박스(마케터)** / **광고주 리드**: 목록 → 탭하면 상세 전체화면 → 상태 변경·전화 걸기·메모(간단 수정).
  필터는 접이식(바텀시트).
- **리드폼·랜딩 목록**: 폴더 트리를 상단 **"폴더: 전체 ▾" 선택 버튼 + 바텀시트**로 접기,
  표 → **카드형 목록**(이름·유형·수익·수정일, 리드/편집/⋯ 버튼).
- **광고주 리포트**.

### Phase 3. 나머지 목록·설정 화면
- 표가 있는 화면(광고주·견적·문자·접속 차단·IP 차단·요소·동의 문서·관리자): 카드형 또는 가로 스크롤 정리.
- 통계·연동·내 정보·광고주 설정/안내: 폼·차트 폭 정리.

### Phase 4. 편집기 — "간단 수정 가능" 수준
- 리드폼·랜딩·견적 편집기: 가로 넘침 제거, 오른쪽 미리보기는 모바일에서 숨기고 **[미리보기] 버튼**으로 전환,
  저장 버튼은 하단 고정. 블록 드래그 등 복잡한 편집은 PC 안내 문구로 대체(기능 제거 아님).

### 검증 (매 단계)
- 375px·1440px 캡처 전후 비교 + 가로 넘침 자동 측정 · `tsc`·`oxlint`·`vitest`.
- 실제 아이폰 확인은 사용자(배포 후).
- 단계 끝날 때 PROGRESS.md 갱신.

## 5. 하지 않는 것
- 공개 랜딩·공개 폼·렌더러 변경, `packages/public-ui` 스타일 변경.
- PC 화면 디자인 변경.
- 편집기 모바일 전용 재설계.
